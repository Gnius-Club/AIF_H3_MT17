🎯 Objetivo de Aprendizaje

Los estudiantes podrán: comprender el pensamiento diagnóstico y la trazabilidad de errores, y usar WebWave y JDoodle para realizar diagnósticos full-stack mediante la lectura de la pestaña Network.

🤖 Prompt de Referencia para XOLO (Solo para Maestro)

⚠️ NOTA: XOLO ya conoce el tema de esta misión. Este prompt es SOLO de referencia en caso de emergencia técnica: 
Explícame qué es un “bug fantasma” y por qué el síntoma puede engañar (se ve en frontend pero nace en backend). Analicemos la metodología de diagnóstico full-stack: seguir el dato desde el clic → Network → respuesta API → lógica del servidor → vuelta a la UI. Guíame para observar qué “pistas” mirar en la pestaña Network (status code, payload, tiempos, formato), y cómo escribir un prompt de diagnóstico que incluya evidencia.

⚡ Puntos Esenciales de la Misión

🎓

Concepto Clave

Pensamiento Diagnóstico: Es como ser un detective de computadoras; en lugar de adivinar qué falló, sigues las pistas del dato desde que haces clic hasta que llega al servidor para encontrar el origen real del problema.

🔧

Habilidad Técnica

Usar la pestaña Network del navegador para rastrear cómo viaja la información entre la página web y el servidor.

🧪

Experimentación

Probar con diferentes códigos de estado (status codes) y formatos JSON para entender las limitaciones de la comunicación entre frontend y backend.

💬

Interacción con XOLO

XOLO ya conoce a cada estudiante y el tema de hoy. Solo abren el chat y comienzan a aprender. Tú guías el timing y motivación.

📊 Diapositiva 3: Brain Spark

1. 💬 Pide a XOLO que te ayude a crear:

"Ayúdame a redactar un prompt de bug report con Vibe Coding: inventa conmigo un bug full-stack hipotético y descríbelo con: esperado vs observado + evidencia de Network (ruta, método, status, fragmento JSON). Guíame a redactarlo con precisión para que un LLM pueda diagnosticar sin adivinar. Ejecuta: entrega el prompt final (listo para copiar/pegar) y una mini plantilla reutilizable para futuros bugs."

2. 🔬 Experimenta y descubre con tu programa:

  • ¿El reporte de bug describe claramente lo que falló?
  • ¿Qué pasa si el status code es 500 en lugar de 404?
  • ¿Funciona igual el diagnóstico si el JSON está mal formado vs si la ruta es incorrecta?
  • ¿Cómo ayuda la trazabilidad a evitar que "adivinemos" la solución de un problema?
  • ¿Por qué es importante usar la IA como apoyo para analizar evidencia y no solo para que nos dé la respuesta final?

"¡Es hora de crear! Vamos a aplicar lo aprendido para redactar reportes de errores profesionales. Imaginen que están trabajando en una app real y encuentran un bug 'fantasma'. Pídanle a XOLO que los ayude a idear este escenario y a redactar un prompt de reporte usando 'Vibe Coding'. El flujo es: idear el bug con XOLO, definir el VIBE del reporte, generar el GCS técnico y probarlo en sus plataformas. Por ejemplo, podrían simular un error donde un botón de compra no funciona porque el inventario en el servidor está mal. Si tienen dudas sobre los códigos de red o el JSON, ¡pregúntenle a XOLO!"
